This project focuses on Salient Information Prompting (SIP) to Steer Content in Prompt-based Abstractive Summarization. The core challenge is to enhance the quality and completeness of summaries generated by Large Language Models (LLMs).
Both proposed implementations integrate the core requirement of the project (SIP) with modern orchestration frameworks (LangChain), parameter-efficient fine-tuning (QLoRA), and factual grounding (RAG), as required for high-stakes applications.
--------------------------------------------------------------------------------
Draft 1: Decoder-Only (DecLLM) Architecture
This approach utilizes widely adopted, instruction-tuned, generative LLMs (DecLLMs), leveraging Prompt Engineering and RAG to impose content control over the inherently abstractive generation process.

Justification/Project Role
Base Model (Generator)
Gemma-7B-it, Mistral-7B-Instruct-v0.1, or Llama-2-7b-chat
These are Decoder-Only (DecLLM) models. Instruction tuning is identified as the key factor for achieving strong zero-shot summarization capability, often performing comparably to much larger models.

Chosen for long document summarization challenges, where long-context encoding disproportionately increases computational cost.

QLoRA (via Hugging Face PEFT)
A Parameter-Efficient Fine-Tuning (PEFT) technique crucial for model alignment. It refines the model's behavior for the specific abstractive task without modifying all parameters, which is essential for optimizing performance on downstream tasks.
B. Salient Information and RAG Pipeline (LangChain Orchestration)
1. Salient Information Prompting (SIP):
    ◦ Keyphrase Extraction: A lightweight model, such as a Longformer-based SigExt or KeyBERT, is implemented to extract phrase-level salient information, which is shown to be superior to word- or sentence-level approaches for summarization performance.
    ◦ Prompt Construction: LangChain is used to dynamically construct prompts that embed the extracted <keywords> (keyphrases) along with the source text. The prompt instructs the LLM to "Consider include the following information: <keywords>". Adding keyphrases improves ROUGE F1 and Recall (R1-r), making summaries more complete.
2. Long Document Handling (Map/Reduce):
    ◦ Since LLMs have context window limits, the Map/Reduce strategy is implemented using LangChain to summarize lengthy inputs (like ArXiv papers) in multiple stages.
    ◦ The document is divided into manageable chunks using a sentence-based chunking strategy. The SIP is applied in the "Map" phase (summarizing individual chunks).
3. Fidelity Management (RAG):
    ◦ RAG is mandatory for high-stakes applications (e.g., academic, legal) to mitigate hallucinations. Hallucinations occur when generated content contradicts the source.
    ◦ The RAG framework retrieves relevant passages from the source document (using vector embeddings) to ground the LLM's response, thus increasing factual accuracy and providing auditability via source citations.
C. Evaluation Metrics
The evaluation phase must move beyond simple lexical overlap to semantic and factual consistency.
• Lexical Metrics: ROUGE-1/-L F1 scores (R1-f, RL-f). ROUGE-L measures the Longest Common Subsequence (LCS), indicating how well the system retains the original summary's essence.
• Semantic Metrics: BERTScore (Precision, Recall, F1). This metric correlates better with human judgment by measuring semantic similarity using contextual embeddings (e.g., from BERT/RoBERTa).
• Human-Aligned Metrics: G-Eval (LLM-as-a-Judge). Used to assess qualitative dimensions like Coherence and Factual Consistency using structured natural language criteria.

Extension Set (Decoder-Only)
Extension 1: Precision-Recall Trade-off Analysis via Keyphrase Count (K) (Max 2.5 pts)
This extension is an ablation study on the core SIP mechanism. The experiment involves systematically testing how the quantity of salient information (K) injected into the prompt affects the quality balance.
1. SIP Parameter Variation: Execute the summarization pipeline repeatedly while varying the number of extracted keyphrases (K). For the ArXiv dataset, recommended values are K=30, 35, 40.
2. Analysis: Measure and plot ROUGE-1 Precision (R1-p), ROUGE-1 Recall (R1-r), and ROUGE-1 F1 (R1-f) across the different K values.
3. Hypothesis Validation: Demonstrate that increasing K generally improves ROUGE Recall (leading to more complete summaries). The analysis must identify the point where increasing K causes a diminishing return or a sharp decrease in ROUGE Precision, highlighting the optimal K that balances detail and conciseness.
Extension 2: Hybrid Hallucination Mitigation using Self-Refine (Max 2.5 pts)
This addresses the challenge that SIP, while improving completeness, can sometimes decrease the AlignScore (faithfulness) for certain DecLLMs (like Mistral). Self-Refine leverages the LLM's own reasoning capabilities to correct factual errors.
1. Iterative Refinement Pipeline (Self-Refine): Implement a multi-step generation process using LangChain sequence/chains, acting as a generator, refiner, and feedback provider:
    ◦ Step 1: Initial summary generation (SIP + RAG).
    ◦ Step 2: Self-Correction Feedback. The LLM is prompted to critique the initial summary specifically for Faithfulness and Consistence based on the RAG-retrieved source content.
    ◦ Step 3: Refinement. The LLM uses the self-generated textual feedback to revise and output the final summary.
2. Fidelity Evaluation: Compare the RAG-only output against the RAG + Self-Refine output.
    ◦ Measure improvement using AlignScore and FactCC, which evaluate factual consistency. The goal is to show that the iterative refinement successfully addresses hallucinations, leading to a higher AlignScore compared to the baseline SIP method.

Draft 2: Encoder-Decoder (RedLLM) Architecture
This approach leverages models like BART and PEGASUS, which use an Encoder-Decoder architecture (sequence-to-sequence). This architecture is well-suited for conditional generation tasks like summarization and offers substantially better inference efficiency after instruction tuning compared to Decoder-Only models.
A. Core Setup and Model Alignment
Component
Technical Choice
Justification/Project Role
Base Model (Generator)
BART-large or PEGASUS
These are pre-trained Transformer models optimized for sequence-to-sequence tasks. BART employs denoising pre-training, while PEGASUS uses Gap Sentence Generation.
Dataset
XSum (Extreme Summarization) or ArXiv
XSum is frequently used for benchmarking BART/PEGASUS and hallucination mitigation techniques like PMIDC.
Fine-Tuning
QLoRA (via Hugging Face PEFT)
Applying QLoRA to a BART/PEGASUS checkpoint (e.g., facebook/bart-large-xsum) refines the model's generation style and content adherence, enhancing the quality-efficiency trade-off.
B. Salient Information and RAG Pipeline (LangChain Orchestration)
1. Salient Information Prompting (SIP):
    ◦ Extraction: Use a method like KeyBERT to generate high-quality, phrase-level keyphrases, as this level of granularity is generally superior.
    ◦ Prompting: The keyphrases are injected into the prompt (e.g., using "Here is a research paper: <text>. Please write a short abstract... Consider include the following information: <keywords>") to steer the abstractive generation toward the salient information.
2. Long Document Handling (Map/Reduce):
    ◦ The Map/Reduce strategy is necessary for long inputs (e.g., ArXiv papers) to break the document into chunks and process them sequentially through the LLM.
    ◦ LangChain handles the initial chunking and the final aggregation, ensuring the abstractive nature is preserved across the reduce steps.
3. Fidelity Management (RAG):
    ◦ RAG is implemented to provide the RedLLM with supporting factual evidence during generation, reducing the risk of generating sentences that are factually inconsistent with the source text. This is vital since abstractive summarization intrinsically carries the critical risk of factual inaccuracy (hallucination).
C. Evaluation Metrics
For Encoder-Decoder models, it is essential to use metrics that can capture the structural quality of the generated sequence.
• Lexical Metrics: ROUGE-1/-L F1, following standard practice.
• Semantic Metrics: BERTScore and BARTScore. BARTScore, which uses a BART model, evaluates generated text quality and relevance to the source document, making it particularly useful for models derived from the BART family.
• Factual Metrics: AlignScore and FactCC.

Extension Set (Encoder-Decoder)
Extension 1: Analysis of Precision-Recall Trade-off via Keyphrase Count (K) (Max 2.5 pts)
This study analyzes how increasing the salient signal influences RedLLM performance, which is vital given the SIP focus.
1. SIP Parameter Variation: Systematically vary K (number of keyphrases) injected into the SIP prompt for the chosen dataset (e.g., K=30,35,40 for ArXiv).
2. Trade-off Analysis: Measure and analyze ROUGE-1 Precision (R1-p), ROUGE-1 Recall (R1-r), and ROUGE-1 F1 (R1-f) across the varying K values.
3. SIP Effectiveness for RedLLM: Analyze if the observed increase in Recall with higher K is accompanied by a positive impact on faithfulness metrics (AlignScore) for the RedLLM architecture, given that this impact is known to be model-specific.
Extension 2: Deep Structural Analysis with Advanced ROUGE Metrics (Max 2.5 pts)
This extension focuses on the structural and long-distance coherence of the generated summaries, providing a more detailed evaluation suitable for generative sequence-to-sequence models like BART and PEGASUS.
1. Implement ROUGE-W (Weighted Longest Common Subsequence):
    ◦ ROUGE-W measures the longest common subsequence (LCS) but favors strings with consecutive matchings.
    ◦ This metric can be computed efficiently using dynamic programming. Comparing ROUGE-W to standard ROUGE-L reveals how the model’s generation manages word order and local coherence.
2. Implement ROUGE-S (Skip-Bigram):
    ◦ ROUGE-S calculates the co-occurrence of any pair of words in their sentence order, allowing for arbitrary gaps.
    ◦ This metric is crucial because it captures long distance dependencies—a key measure of fluency and structural coherence, especially important when evaluating abstractive models against human-written summaries.
3. Analytical Comparison: Present a detailed comparison showing how the BART/PEGASUS outputs score across ROUGE-L, ROUGE-W, and ROUGE-S. This sophisticated metric analysis ensures the project achieves comprehensive evaluation quality.

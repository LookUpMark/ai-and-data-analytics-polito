> [!summary] **Document Summary**
> Full tour of IPv6: why it exists (address-space exhaustion, routing scalability), how 128-bit addresses were chosen (RFC 1715 efficiency), address notation and the address-space map (global unicast, link-local, unique local, multicast, anycast, special addresses), the simplified 40-byte header with extension-header chaining, ICMPv6 (which absorbs ARP and IGMP), Neighbor Discovery and Duplicate Address Detection, stateless/stateful address autoconfiguration (EUI-64, privacy extensions, Router Advertisement M/O flags, DHCPv6), and how routing protocols support both address families (integrated vs. ships-in-the-night).

## Motivation and History

**Why a new version of IP?** Only one true answer: **a larger address space**. Additional answers given by the slides (more efficient on LANs, multicast/anycast, security, policy routing, plug-and-play, traffic differentiation, mobility, QoS) were largely **ported back to IPv4**; the notable exception is policy routing — IPv4 routing follows topology, IPv6 enables finding the most *economic* path.

**Why IPv4 addresses are scarce:**

- 32-bit addresses ≈ 4 billion total, but only ~3.5 billion usable (class reservation, multicast).
- Hierarchical assignment: prefixes assigned to one physical network cannot be reused elsewhere (lots of unused addresses, e.g., a class B /16 partially used).
- Demand: ~4 billion home accesses, ~5.5 billion mobile phones, IoT adding ~50 billion devices.

**Interim IPv4 solutions:** subnetting/netmasks, private addresses (RFC 1918) + NAT/ALG. NAT breaks end-to-end reachability, increases gateway processing, adds complexity.

**Who assigns addresses:** IANA assigns /8 blocks to RIRs (AFRINIC, APNIC, ARIN, LACNIC, RIPE NCC); RIRs split blocks to NIRs/LIRs. Each IPv4 address is in one of five states: reserved, IANA unallocated, RIR unassigned, assigned-but-not-advertised, assigned-and-advertised (BGP).

**Routing scalability** is the second driver: BGP table growth strains backbone routers (resource limits, route churn). CIDR aggregation helps but is limited by non-rational prefix assignment — a problem IPv6 wanted to solve and that **is still open**.

**Birth of IPv6:** IETF Boston 1992 "Call for proposals for IPng". Proposals: TUBA (OSI CLNP), CATNIP (integrate IP/CLNP/IPX), **SIPP** (incremental over IPv4) — winner: **SIPP with 128-bit addresses**.

### Why 128 bits?

RFC 1715 addressing efficiency `H = log10(number of addresses) / number of bits`, with H between 0.14 (pessimistic) and 0.26 (optimistic) in real networks:

| Bits | Pessimistic (0.14) | Optimistic (0.26) |
|---|---|---|
| 32 | 3·10⁴ | 2·10⁸ |
| 64 | 9·10⁸ | 4·10¹⁶ |
| 80 | 1.6·10¹¹ | 2.6·10²⁷ |
| 128 | 8·10¹⁷ | 2·10³³ |

Final decision: 128 bits → assuming one million billion stations, ≥10⁷ bits even at minimum efficiency; ≈ 6.5·10²³ addresses per m² of Earth surface.

## Notation

- 8 groups of 4 hex digits separated by `:` (`x:x:x:x:x:x:x:x`), each group = 2 bytes.
- **Rule 1**: leading zeros in each group can be omitted → `1080:0:0:7:200:A00C:3423:A089`.
- **Rule 2**: one (and only one) run of all-0 groups can be replaced by `::` → `1080::7:200:A00C:3423:A089`. Using `::` twice is **not allowed** (ambiguity).

## Address Structure and Prefixes

> [!definition] **Prefix**
> IPv6 replaces address/netmask with `address/N` (N = prefix length in bits). **No address classes.** Usual structure: n-bit prefix + (128−n)-bit Interface ID; the Interface ID is **usually 64 bits** (but not always).

Routing/addressing principles are the same as IPv4: a *subnetwork* is a set of hosts with the same prefix; a *link* is the physical network; on-link hosts share the prefix and communicate directly, off-link hosts need a router.

## The Address Space Map

| Type | Prefix | Notes |
|---|---|---|
| Global unicast (aggregatable) | `2000::/3` (shown as 2000::–3FFF::) | Globally routable; equivalent to public IPv4 |
| Unique local (ULA) | `FC00::/7` | Private use; only `fd00::/8` (L flag = 1) valid today |
| Link-local | `FE80::/64` (from FE8F::–FEB0:: range shown) | Single link; autoconfiguration, neighbor discovery |
| Site-local | `FEC0::/10` | **Deprecated** |
| Multicast | `FF00::/8` | Replaces 224.0.0.0/4 |
| IPv4-embedded | `::ffff:x.y.z.w` (96 bits zero/FFFF + 32-bit IPv4) | Aids transition |
| Loopback | `::1` | Equivalent of 127.0.0.1 |
| Unspecified | `::` (all 0s) | Source-only; used in DAD |

### Global unicast addresses

Format: `001 | Global Routing Prefix (n bits) | Subnet ID (m bits) | Interface ID` — slides show the common 48/16/64 split. Assignment is topology-based with effective aggregation. Former structure: TLA ID (13 bits) / NLA ID (32 bits) / SLA ID (16 bits) / Interface ID (64 bits) under multi-level authorities.

### Unique local addresses (ULA)

- `FC00::/7`; the 8th bit is the **L (Local) flag**: `fc00::/8` (L=0, may be defined in the future), `fd00::/8` (L=1, locally assigned) — **fd00::/8 is the only valid ULA range today**. Format: `1111 1101 | random 40-bit Subnet ID | 16-bit subnet | 64-bit Interface ID`.

### Multicast addresses

- `FF00::/8`, subdivided into:
  - **Well-known multicast** `FF00::/12` — predefined groups (e.g., routers);
  - **Transient** `FF10::/12` — dynamically assigned by multicast applications;
  - **Solicited-node multicast** `FF02:0:0:0:0:1:FF00::/104` + low 24 bits of an address (see Neighbor Discovery).
- A **scope** field defines how broadly the packet propagates (link, site, global...).

### Anycast

> [!definition] **Anycast address**
> An address assigned to **more than one interface** (typically on different devices). A packet sent to it is routed to the **"nearest"** interface having that address according to the routing table. Initially designed for DNS; still experimental.

### Special-address rules

- **Loopback `::1`**: cannot be assigned to a physical interface; must not leave the device; routers never forward it; a device must drop a received packet addressed to ::1.
- **Unspecified `::`**: used as source to indicate absence of an address; cannot be assigned; used in DAD.
- **IPv4-mapped**: IPv4 address in the low 32 bits, e.g., `::ffff:20.10.4.3`.

## What Changes in the Protocol Architecture

| IPv4 component | IPv6 counterpart |
|---|---|
| IP | IPv6 |
| ICMP | ICMPv6 |
| ARP | **integrated in ICMPv6** (Neighbor Discovery) |
| IGMP | **integrated in ICMPv6** (MLD) |

Upgraded but conceptually unchanged: DNS (**AAAA records**), RIP/OSPF, BGP/IDRP, TCP/UDP, socket interface.

## Packet Header

**IPv6 header is fixed-length: 40 bytes.**

Removed with respect to IPv4:

- **Header checksum** — redundant (L2 checks, TCP/UDP checksums; **UDP checksum becomes mandatory** in IPv6).
- **Fragmentation fields** — IPv6 routers **do not fragment** packets they forward; packets larger than MTU are dropped with an ICMPv6 *Packet Too Big* back to the source (source-only fragmentation via the Fragment extension header).
- **Header Length** — fixed at 40 bytes.

### Extension headers

- **Next Header** field ≈ IPv4 Protocol field; extension headers chain via their own Next Header fields.
- Same code values as IPv4 plus new ones: 0 Hop-by-Hop, 6 TCP, 17 UDP, 43 Routing, 44 Fragment, 50 ESP, 51 Authentication, 60 Destination options, **59 = no next header**.
- Format: `Next header | Length | Extension data`.
- **Hop-by-Hop** (must immediately follow the IPv6 header): options as TLV triplets examined by every router; e.g., **Jumbogram** option (payload > 65,535 bytes).
- **Routing**: source routing (not usable in practice — conflicts with router routing tables).
- **Fragment**: source splits packets; receiver reassembles.
- **AH / ESP**: used by IPsec — AH guarantees authenticity/integrity; ESP adds encryption.

## Interfacing with Lower Layers

- IPv6 is a **new EtherType (0x86DD)** on Ethernet — treated as a new protocol, which is what enables dual-stack.
- Destination MAC for unicast: discovered procedurally via **Neighbor Discovery**; for multicast: **algorithmic mapping**.

### Multicast MAC mapping

MAC `33-33-xx-xx-xx-xx` (RFC 7042): the **lower 32 bits of the MAC are copied from the lower 32 bits of the IPv6 multicast address**. Example: `FF0C::89:AABB:CCDD` → MAC `33:33:AA:BB:CC:DD`. NICs can filter Ethernet multicast (unlike broadcast).

## Neighbor Discovery (ND)

ND substitutes ARP and is based on **multicast** and the **Solicited-node Multicast Address**:

> [!definition] **Solicited-node multicast address**
> Automatically created for every unicast address on an interface: `FF02::1:FF/104` + the **24 least significant bits** of the IP address. Via the general IPv6→MAC rule, it maps to MAC `33-33-FF-xx-xx-xx` (the low 32 bits of the solicited-node address are `FF` + those 24 bits, e.g., `ff02::1:ff00:100` → `33-33-ff-00-01-00`). Most likely only one station is in each group.

**Address resolution flow:**

1. Host sends an **ICMPv6 Neighbor Solicitation** (type 135) to the solicited-node multicast address of the target IPv6 address (e.g., dst `ff02::1:ff00:100`, MAC `33-33-ff-00-01-00`), carrying the message "I need the MAC address of 2001:db8:cafe:1::100".
2. The target replies with a **Neighbor Advertisement** (type 136) **to the requester's unicast address**.
3. The IPv6↔MAC mapping is stored in the neighbor cache (equivalent of the ARP cache); the option field carries the sender's link-layer address.

## ICMPv6

Encapsulated in IPv6 (Next Header = 58), at most 576 bytes. Format: `Type | Code | Checksum | Message Body`.

| Type | Message | Notes |
|---|---|---|
| 1 | Destination Unreachable | error (<128); code gives reason (no route, wrong scope, addr/port unreachable) |
| 2 | Packet too big | error — routers no longer fragment |
| 3 | Time exceeded | error — Hop Limit = 0 |
| 4 | Parameter problem | error — bad header/extension field |
| 128/129 | Echo Request/Reply | ping |
| 130/131/132 | Multicast Listener Query/Report/Done | group management (replaces IGMP) |
| 133/134 | Router Solicitation/Advertisement | new in ND |
| 135/136 | Neighbor Solicitation/Advertisement | replaces ARP |
| 137 | Redirect | better first-hop |

Types **< 128 are errors**, **≥ 128 informational**.

## Multicast Group Management (MLD)

- Within a link: data-link multicasting with the IPv6→MAC mapping.
- Among links: routers query on-link members (Multicast Listener Query, type 130 — general or group-specific); listeners report (type 131) to the all-routers multicast address; when leaving, they send **Listener Done** (type 132). Multicast routing protocols then propagate group location across links.

## Device Configuration

Information needed: address prefix, interface identifier, default gateway, DNS server, hostname, domain name, MTU...

| Option | How |
|---|---|
| Manual | by hand |
| Stateful | everything from DHCP |
| Stateless (SLAAC) | prefix from Router Advertisements; Interface ID auto-generated |
| Hybrid (stateless DHCP) | address autoconfigured; **other** info via DHCP |

### Interface identifier

- Manual, DHCPv6, or auto-generated from **EUI-64**:
  - EUI-48 MAC split OUI(24) | 24 manufacturer bits; insert `FF:FE` in the middle; flip the universal/local (7th) bit of the first byte → 64-bit Interface ID.
- **Privacy concerns**: the low 64 bits never change if derived from the MAC → traceability. **RFC 4941 privacy extensions**: a random/previous "privacy" address and the MAC-derived ID are hashed (MD5), producing a random interface ID stored for the next configuration. A host may hold several addresses simultaneously ("default" and "privacy-aware") and choose which to use for accepting/initiating connections.

### Router/Prefix Discovery

- Routers send **Router Advertisement** (type 134): solicited (answering a Router Solicitation sent to all-routers `FF02::2`) or **unsolicited/periodic**.
- RA fields: **M** (Managed — address via DHCP), **O** (Other configuration — e.g., DNS via DHCP), Cur Hop Limit, Router Lifetime, Reachable Time, Retrans Timer.
- Options (length in multiples of 8 bytes):
  - **Prefix Information** (type 3): prefix, prefix length, valid/preferred lifetime; flags **L** (on-link) and **A** (autonomous config usable);
  - **MTU** (type 5): ensures all hosts on-link use the same MTU;
  - **Link-Layer Address** (type 1... per slide "Link Layer Address Option").

### Duplicate Address Detection (DAD)

- Probe uniqueness by sending a **Neighbor Solicitation with the probed address as target**, to the corresponding solicited-node multicast (source = all-0s unspecified address).
- Wait ≥ 1 s: no answer → address is valid; an answer → stop (duplicate).

### Stateless configuration sequence

1. Generate a **link-local** address; run DAD on it; subscribe to its solicited-node multicast; send a Multicast Listener Report → on-link communication enabled.
2. With a router: send Router Solicitation / listen to RAs; create a global address from the advertised prefix; DAD again.
3. **Renumbering**: keep listening to RAs — addresses move between *preferred* and *deprecated* states; switching ISP prefixes is easier than in IPv4.

### Stateful (DHCPv6)

Client/server, triggered by **M=1** in the RA. Messages: Solicit (to all-agents `FF02::1:2`), Advertise, Request, Reply, Release, Reconfigure. **Stateless DHCP**: M=0, O=1 — address from SLAAC, other parameters from DHCP.

### Scoped addresses

`address%zone` (e.g., `FE80::0237:00FF:FE02:a7FD%19`) — the OS appends the interface index to disambiguate identical link-local addresses on different interfaces.

## Routing with IPv6

- Same two phases as IPv4: **on-the-fly routing** (forwarding, uses the routing table) and **proactive routing** (building tables: static config or routing protocols).
- Dual-family deployment styles:
  - **Integrated routing**: a single protocol advertises destinations of both families;
  - **Ships in the night**: each address family uses a distinct, completely independent protocol.
